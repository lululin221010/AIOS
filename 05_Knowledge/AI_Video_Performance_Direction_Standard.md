## 一、這套方法解決什麼

不是要找到一條「神 Prompt」，而是建立一個可重複的翻譯流程：

**故事 → 角色心理 → 可觀察演技 → 秒級情緒弧線 → AI 影片 Prompt**

「她很傷心」「他非常憤怒」是創作者對人物心理的理解，不是好的表演指令。
影片模型真正需要的是：觀眾到底會看到什麼、聽到什麼，才知道這個人物正在傷心、憤怒、害怕、心虛或動搖？

## 二、固定三層骨架

所有正式導演 Prompt 原則上使用三層結構。

### Layer 1｜全劇控制
負責建立片場與一致性：總時長／場景年代環境／特殊光影／人物外觀一致性／服裝／聲音／影像風格／必要的一致性限制。
原則：這一層夠用即可，不要把篇幅浪費在「cinematic、masterpiece」之類堆疊詞，把 Prompt 預算留給人物表演。

### Layer 2｜鏡頭時間軸
先按 SHOT 分級，再在每個鏡頭裡分秒級節拍（例：SHOT 1｜0–7秒，內部再切0–3秒／3–7秒）。不要把整支影片寫成沒有鏡頭層級的一整串時間碼。

### Layer 3｜表演控制
這是真正的演技層。原教程稱「八維表演公式」；依實際工作拆解，AIOS實作固定保留**九個欄位**，不為湊八維而刪資訊（原名保留作來源標記）：
1. 時間段　2. 人物目的　3. 情緒變化　4. 台詞觸發　5. 面部動作＋AU　6. 目光＋身體　7. 聲音　8. 呼吸＋停頓　9. 結束狀態／靜止反應

## 三、九欄表演控制細節

**① 時間段**：這個表演節拍發生在幾秒到幾秒。

**② 人物目的 WHY**：不要先問「他現在是什麼情緒」，先問「他現在想做什麼」（想反擊／想證明犧牲／想隱藏受傷／想維持尊嚴／想逼對方承認／想說秘密又不敢說）。目的產生表演，情緒不是孤立貼紙。

**③ 情緒變化**：人物不能無理由從A情緒瞬間跳到B。必須設計中間變化。

> **保護層規則**：先判斷這場戲是否存在「保護層」。若有，描述 建立→受壓→裂縫→失效／重新穩住（例：受傷→用憤怒防衛→防衛被刺激→出現裂縫→試圖重新控制→控制失敗→悲傷露出）。**禁止硬套**——曖昧、驚喜、懸疑等戲可能根本沒有崩塌，不為套公式而強加保護層。

**④ 台詞觸發**：台詞本身就是表演時間軸。不寫「她悲傷地說：……」，而寫「說到某個詞時……該詞後停頓0.5秒……最後一個詞結束後……」，要知道哪個字/句讓人物發生變化。

**⑤ 面部動作＋FACS/AU**：固定順序＝**先看見→用人話描述→AU校準**。先寫可觀察的東西（眉毛內側緩慢抬起、嘴角輕微下沉……），再視需要加AU編號+強度。AU不是情緒公式，同一AU配不同眼神/姿勢/嘴部/身體會形成完全不同心理閱讀。並描述 onset→peak→offset（開始→峰值→消退），不要讓表情第一幀就100%。**AU是否被特定模型穩定理解，屬CC實測事項。**

**⑥ 目光＋身體**：看誰／何時移開／移開多久／何時看回；頭部/肩膀/手/軀幹/重心/物件互動。不要讓所有心理都靠臉演。

**⑦ 聲音**：若模型/後製支援，指定音量/音高/語速/重音/氣息/顫抖/破音，且要指定變化發生在哪個詞。

**⑧ 呼吸＋停頓**：哪裡吸氣/吐氣/停/停多久，且要回答「人物為什麼停」（例：她正在決定要不要把最脆弱的那句話說出口）。停頓期間人物仍在表演。

**⑨ 結束狀態＋靜止反應**：每個節拍要知道人物最後停在哪，才能接下一段。可明確寫「16秒以前禁止破音」「20秒以前眼眶可以濕潤但禁止眼淚落下」——**禁止提前反應**，關鍵反應必須在指定觸發點才出現。

## 四、AIOS 延伸原則：克制優先

老師教的是控制表演；AIOS再加一層：**不要把「情緒強烈」誤認成「演技好」**。很多時候「想哭但不能哭」比「嚎啕大哭」更有戲。真正有戲的往往是「角色想做的事」與「角色不能做的事」之間的衝突。但克制不是所有戲的固定答案，需要爆發時仍可爆發，前提是有累積、有觸發、有過程。

## 六、生成前 Gate 檢查表

- [ ] 是否使用三層骨架？
- [ ] 是否先寫人物「想做什麼」，而不是只貼情緒？
- [ ] 抽象心理是否已翻譯成看得見／聽得到的證據？
- [ ] 是否有秒級節拍？
- [ ] 台詞是否真正與表演變化綁定？
- [ ] 情緒是否有過程，而不是A突然跳B？
- [ ] 若存在保護層，是否描述其建立→受壓→裂縫→失效／穩住？
- [ ] 沒有保護層的戲，是否避免硬套？
- [ ] 是否先用自然語言，再用AU校準？
- [ ] 表情是否有onset→peak→offset？
- [ ] 是否指定禁止提前出現的關鍵反應？
- [ ] 有沒有把悲傷自動等同哭泣？把憤怒自動等同咆哮？
- [ ] 是否允許人物停頓、不動、欲言又止？
- [ ] 台詞、臉、身體是否只是重複同一情緒？
- [ ] 每個節拍是否有結束狀態？
- [ ] 是否把尚未實測的模型能力誤寫成一定可做到？

## 七、CC 工程審查（2026-08-24）

### 7.1 待驗證清單（GPT/Grok原提出，內容有效，逐項需CC實測）
秒級觸發服從度／禁止提前反應服從度／情緒漸變vs模型跳狀態／onset-peak-offset可控性／自然語言vs自然語言+AU差異／AU強度有效性／20-30秒長表演穩定性／多人對手戲台詞歸屬／人物一致性／成本與重生成需求。這套驗證項目設計得很扎實，可以直接拿來當測試腳本骨架，沒有異議。

### 7.2 ⚠️ 重大衝突：小雲雀/Seedance 2.5 不是「可小額測試的新候選」，是已被正式排除的供應商
